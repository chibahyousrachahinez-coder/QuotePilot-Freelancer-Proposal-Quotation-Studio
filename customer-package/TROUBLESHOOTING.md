# QuotePilot Troubleshooting Guide

Quick diagnostic solutions for common questions regarding PDF printing, data persistence, and local setup.

---

## 1. PDF Export / Print Issues

### Issue A: Background colors, badges, or dark cards are missing in the PDF
**Cause:** Most modern browsers (Chrome, Safari, Edge) disable background graphics by default when printing web pages to conserve physical printer ink.
**Solution:**
1. Click **Export / Print PDF** in QuotePilot to trigger the print dialog.
2. In the print dialog, look for the **More settings** or **Options** dropdown.
3. Check the box labeled **Background graphics** (or **Print backgrounds** in Safari).
4. Ensure **Color mode** is set to **Color** (not Black & White).
5. The preview will immediately update to show all deep charcoal cards, emerald badges, and neutral table headers.

### Issue B: Browser headers and footers (URL, page numbers, date) appear on the PDF
**Cause:** The browser automatically inserts browser metadata around printed pages.
**Solution:**
1. In the print dialog, open **More settings**.
2. **Uncheck** the box labeled **Headers and footers**.
3. Set **Margins** to **Default** or **None**.

### Issue C: Content breaks awkwardly across page edges
**Solution:**
- In the print dialog, adjust the **Scale** setting (typically set to **Fit to page** or custom **95%**).
- QuotePilot’s printable container is designed with CSS page-break rules, but adjusting scale ensures custom multi-item tables fit onto your desired page count.

## 2. Data Persistence & Backup Issues

### Issue A: "I reopened QuotePilot and my proposals are missing"
**Potential Causes:**
1. **Private / Incognito Window:** If you used QuotePilot inside an Incognito or Private Browsing window, the browser automatically destroys all `localStorage` when the window is closed.
2. **Aggressive Cache Cleaner:** Some browser extension cleaners (or privacy modes) purge local site storage when closing the browser.
3. **Different Browser:** Data stored in Chrome will not automatically show up in Safari or Firefox unless imported.

**Solution:**
1. Avoid using Private / Incognito mode for daily proposal drafting.
2. Open **Settings** > **Data Management & Backup**.
3. Click **Import JSON** and select your latest `quotepilot_backup_*.json` file.
4. All your proposals, clients, and settings will instantly reappear.
5. *Pro Tip: Make it a habit to export a JSON backup at the end of each week or after finishing a major proposal.*

### Issue B: "Import failed: Invalid JSON backup format"
**Cause:** The file selected was not a valid backup file generated by QuotePilot, or the file was corrupted/edited manually with syntax errors.
**Solution:**
1. Ensure the file extension is `.json`.
2. Open the file in a text editor to confirm it begins with `{"app":"QuotePilot", ...}`.
3. If you manually edited the JSON, verify that all brackets and quotation marks are balanced using an online JSON validator (like jsonlint.com).

## 3. Settings & Proposal Updates

### Issue A: "I updated my studio name/email in Settings, but an existing proposal still shows my old information"
**Cause:** By design, QuotePilot preserves a snapshot of your studio profile and financial rates at the moment each proposal is generated. This ensures that historical contracts are not retroactively altered when you change your rates or branding in the future.
**Solution:**
- To update an existing proposal to reflect new settings, open the proposal in the **7-Step Wizard** (`Edit Proposal`), review the fields, and click **Save**.
- All newly created proposals will automatically adopt your updated Settings defaults.

## 4. Local Development & Installation Issues

### Issue A: `command not found: npm` or `command not found: node`
**Cause:** Node.js is not installed on your system or is not present in your system PATH.
**Solution:**
1. Visit [nodejs.org](https://nodejs.org) and download the recommended LTS version (v18 or higher).
2. Follow the installer instructions for your operating system (macOS, Windows, or Linux).
3. Re-open your terminal and run `node -v` to confirm installation.

### Issue B: `Port 3000 is already in use`
**Cause:** Another application or background process is already using port 3000.
**Solution:**
Vite will automatically suggest using another port (e.g., `3001`). You can also specify a custom port in your command line:
```bash
npm run dev -- --port 4000
```

### Issue C: Dependencies fail to install (`npm install` error)
**Solution:**
1. Ensure you have network connectivity.
2. Clear npm cache and retry:
   ```bash
   npm cache clean --force
   npm install
   ```
